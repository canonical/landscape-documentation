# 26.10 release notes

> Database schema changes are required to upgrade to Landscape Server 26.10.

You can now access Landscape 26.10 in our `latest-stable` rolling release PPA: `ppa:landscape/latest-stable`.

Note that 26.10 is not an LTS release. For self-hosted production deployments, we recommend using an LTS release, such as {ref}`Landscape Server 26.04 LTS <reference-release-notes-26-04-lts>`.

## Highlights

- **Package change plans**: Plan a package change across multiple instances before you run it, using the REST API. A plan can install, remove, upgrade, hold, unhold, or change the version of packages. Each plan is limited to 100 instances and 500 packages. Package change plans are enabled by default on self-hosted Landscape and are controlled by the `package_change_plans` key under `[features]` in the `service.conf` file.

- **Package search**: Search for packages across instances with the REST API endpoints `POST /packages:search` and `POST /packages:search-upgrades`, or in a single instance with `GET /computers/{computer_id}/packages/search`. Package search is enabled by default on self-hosted Landscape and is controlled by the `package_search_rest_api` key under `[features]` in the `service.conf` file.

- **Compliance report**: `GET /computers/compliance-report` returns a compliance and security report for up to 10,000 instances. It is enabled by default on self-hosted Landscape and is controlled by the `instance_reports` key under `[features]` in the `service.conf` file.

- **Web portal URL**: The web portal is now served at `/portal/` instead of `/new_dashboard/`. Requests to `/new_dashboard/` are redirected to `/portal/` with an HTTP 301 response. Users go to the web portal after login when the `login_to_portal` key under `[features]` in the `service.conf` file is enabled, which is the default on self-hosted Landscape.

## Additional Updates

- `GET /packages` and `GET /computers/{computer_id}/packages` are deprecated in the REST API v2. They remain available, and their responses include a `Deprecation` header
- Legacy web UI endpoints that change state, including upgrade profile removal, now require `POST` requests
- WSL profile and USG profile limits no longer apply on self-hosted Landscape
- The `service.conf` file shipped with Landscape Server now sets `computer_soft_deletion = true` under `[features]`
- The Ubuntu installer attach service (`[ubuntu_installer_attach]`) and the WSL hostagent service (`[hostagent_server]`) can now serve TLS when `ssl_server_cert` and `ssl_server_private_key` are set in their section
- Added `PATCH /access-groups/{access_group_name}` to edit an access group
- Added `POST /person:test-email` to send a test email
- Added `POST /users:edit`, which can clear optional fields. `PUT /users` now rejects an empty `location`
- Added `GET /computers/{computer_id}/users/{username}/pending-activities`
- `GET /me` now includes the person's global roles
- Activity responses now include the computer title
- Script profiles can now be searched with the REST API
- Upgrade profiles that missed their run window are now skipped
- Improved performance of profile scheduling, alert checks, pending message queries, hardware info message handling, duplicate computer checks, and activity search for soft-deleted computers

## Upgrade

Database schema changes are required to upgrade to Landscape Server 26.10. You can follow the existing guide to upgrade: {ref}`how-to-upgrade`.

- The OIDC redirect page is now `/portal/handle-auth/oidc` instead of `/new_dashboard/handle-auth/oidc`, and the Ubuntu One redirect page is now `/portal/handle-auth/ubuntu-one/`. See {ref}`how-to-external-auth-oidc`.
- The `landscape_profiles.sh` cron job is replaced by `upgrade_profiles.sh`, `scheduled_profiles.sh`, `script_profiles.sh`, `usg_profiles.sh`, and `cancel_expired_activities.sh`. Each writes to its own log file instead of `landscape-profiles.log`. See {ref}`how-to-manage-maintenance-cron-jobs` and {ref}`reference-logs`.
- The Apache configuration template shipped with Landscape Server now proxies both `/portal` and `/new_dashboard` to the dashboard service.

## Bug fixes

- Fixed an HTTP 500 error when a computer has multiple contracts
- Scheduled profiles no longer run on disabled accounts
- Fixed a licensing issue when a client reports Ubuntu Pro information
- The removal profile days limit is now enforced
- Fixed the unapproved activity count when a person has multiple accounts
- The maintenance script now handles each account independently
- The root URL and system email are now read from `service.conf`
- A WSL host's simulated Ubuntu Pro status is now reported as attached
- The `landscape-server` package post-installation script no longer runs a recursive `chown` on `/var/lib/landscape-server` [LP: #1725282](https://bugs.launchpad.net/landscape/+bug/1725282)
- The repository mirror error message now links to the migration guide
- Added validation of LDAP identity values to prevent LDAP injection
