# 26.10 release notes

```{note}
Landscape 26.10 is not an LTS release. For self-hosted production deployments, we recommend using an LTS release, such as {ref}`Landscape Server 26.04 LTS <reference-release-notes-26-04-lts>`.
```

You can now access Landscape 26.10 in our `latest-stable` rolling release PPA: `ppa:landscape/latest-stable`.

Database schema changes are required to upgrade to Landscape Server 26.10.

## Highlights

- **Package change plans (REST API)**: Plan a package change across multiple instances before executing it. A package change plan can install, remove, upgrade, hold, unhold, or change the version of packages. You can create, list, inspect, delete, and execute plans, review a plan's items, summary, and exclusions, and exclude packages from a plan. A plan is limited to 100 instances and 500 packages. Plans are scoped to the person who created them. Expired plans are deleted by the new `process_package_change_plans.sh` cron job. Package change plans are enabled by default on self-hosted Landscape, and are controlled by the `package_change_plans` key under `[features]` in the `service.conf` file.

- **Package search (REST API)**: Search for packages across instances with `POST /packages:search` and `POST /packages:search-upgrades`, or search a single instance with `GET /computers/{computer_id}/packages/search`. Package search results are limited to the instances that the person is allowed to view packages on. Package search is enabled by default on self-hosted Landscape, and is controlled by the `package_search_rest_api` key under `[features]` in the `service.conf` file.

- **Compliance report (REST API)**: A new `GET /computers/compliance-report` endpoint returns a compliance and security report for a selection of instances. The report is limited to 10,000 instances. It is enabled by default on self-hosted Landscape, and is controlled by the `instance_reports` key under `[features]` in the `service.conf` file.

- **Web portal moved to `/portal/`**: The web portal is now served at `/portal/` instead of `/new_dashboard/`. Requests to `/new_dashboard/` are redirected to the matching `/portal/` URL with an HTTP 301 response. After login, users are taken to the web portal by default. You can control this with the `login_to_portal` key under `[features]` in the `service.conf` file; it is enabled by default on self-hosted Landscape.

## Behavior changes

- **Web portal URL and authentication redirect pages**: The OIDC redirect page is now `/portal/handle-auth/oidc` (previously `/new_dashboard/handle-auth/oidc`) and the Ubuntu One redirect page is now `/portal/handle-auth/ubuntu-one/`. See {ref}`how-to-external-auth-oidc` for OIDC configuration.

- **Profile cron job split**: The `landscape_profiles.sh` cron job has been replaced by separate scripts in `/opt/canonical/landscape/scripts`, each run every five minutes: `upgrade_profiles.sh`, `scheduled_profiles.sh`, `script_profiles.sh`, `usg_profiles.sh`, and `cancel_expired_activities.sh`. The `landscape-profiles.log` file is replaced by a log file for each script in `/var/log/landscape-server/`. See {ref}`how-to-manage-maintenance-cron-jobs` and {ref}`reference-logs`.

- **State-changing legacy web UI requests require `POST`**: Several legacy web UI endpoints that change state, including upgrade profile removal, now require `POST` requests.

## Deprecations

- The following REST API endpoints are deprecated in v2. Responses from these endpoints include the `Deprecation` and `X-Deprecated-Api-Version` headers, and a `Link` header pointing to the documentation. They remain available, but will not be carried forward into v3 of the REST API:

  - `GET /packages`
  - `GET /computers/{computer_id}/packages`

## Additional updates

- **WSL and USG profile limits removed on self-hosted**: Self-hosted Landscape no longer applies the WSL profile and USG profile limits.

- **Computer soft deletion**: The `service.conf` file shipped with Landscape Server now sets `computer_soft_deletion = true` under `[features]`. Soft-deleting a computer now queues a deletion task.

- **TLS for gRPC services**: The Ubuntu installer attach service (`[ubuntu_installer_attach]`) and the WSL hostagent service (`[hostagent_server]`) can now serve TLS directly when you set `ssl_server_cert` and `ssl_server_private_key` in the section. Without these keys, the ports remain plaintext.

- **REST API additions**:

  - `PATCH /access-groups/{access_group_name}` edits an access group.
  - `POST /person:test-email` sends a test email.
  - `POST /users:edit` edits a user and supports clearing optional fields. `PUT /users` now rejects an empty `location`.
  - `GET /computers/{computer_id}/users/{username}/pending-activities` lists pending activities for a computer user.
  - Script profile search is now supported.
  - `GET /me` now includes the person's global roles.
  - Activity responses now include the computer title.

- **Upgrade profiles**: Upgrade profiles that missed their run window are now skipped.

- **WSL**: A WSL host's simulated Ubuntu Pro status is now reported as attached.

- **Dependencies**: `binutils` is no longer a dependency of the `landscape-server` package. The `landscape-server` package now requires `landscape-dashboard` 26.10~rc1 or later.

- **Performance**: Performance improvements for profile scheduling, alert checks, pending message queries, hardware info message handling, duplicate computer checks, and activity search for soft-deleted computers. TOAST bloat in the `computer_packages` table is reduced.

## Bug fixes

- Fixed a 500 error when a computer has multiple contracts.
- Fixed scheduled profiles running on disabled accounts.
- Fixed a licensing bug when a client reports Ubuntu Pro information.
- Fixed the removal profile days limit not being enforced.
- Fixed the maintenance script so that it handles accounts independently.
- Fixed scheduled profiles not being remapped when their access group is deleted.
- Fixed the unapproved activity count when a person has multiple accounts.
- Fixed `service.conf` not being the source of truth for the root URL and system email.
- Fixed message type labels not being normalized.
- Removed a blocking recursive `chown` of the repository pool (LP: [#1725282](https://bugs.launchpad.net/landscape/+bug/1725282)).
- Updated the repository mirror error message to link to the migration guide.

## Security fixes

- Fixed LDAP identity validation to prevent injection.
- Package search results are now limited to the instances that the person is allowed to view packages on.

## Upgrades

Database schema changes are required to upgrade to Landscape Server 26.10. For general upgrade steps, see {ref}`how-to-upgrade`.

If you use Apache configuration that you maintain yourself, note that the Apache configuration template shipped with Landscape Server now proxies both `/portal` and `/new_dashboard` to the dashboard service.
